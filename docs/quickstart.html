extract-text quick start

Read eviction court documents (e-filed PDFs, scanned PDFs, TIFFs) into a table of party names, the defendant's service address, the plaintiff's attorney, and case details. Everything runs on your own computer.

extract-text has two engines. The deterministic engine uses written rules and the layout of the page, with no AI of any kind. The AI engine shows each page to a language model that runs on your own machine. You can run either one, or both side by side. This page gets you from nothing to a finished table with whichever you choose. The full detail is in the manual.

1. Choose an engine

Deterministic

Rules and page geometry only. No AI, no model files, no network. The same document always gives the same answer, and every value records the rule and the spot on the page it came from.

Choose it when AI tools are not permitted on your machines, or when results must be reproducible and auditable.

AI

A vision language model (qwen3.5 9B) reads a picture of the page through Ollama, a program on your own computer. It handles handwriting and layouts the rules were never written for.

Choose it when AI is allowed and your documents include handwriting or unusual forms. Best used alongside the rules, not alone.

Both

Rules fill the main columns and the AI's answers sit beside them, never blended. Every disagreement is measured and flagged, which tells you which documents a person should check.

The recommended mode whenever you are allowed to use AI.

If your organization does not allow AI on its computers, the deterministic engine is complete on its own. It needs no AI software installed, nothing else in the package depends on the AI engine, and you can skip every AI step on this page.

Two helper programs (every engine needs these)

poppler opens PDF files, and tesseract reads scanned pages (optical character recognition, or OCR). Both are free, and you install them once from your system's package manager.

On Windows this is usually the hardest step. The checkup below names anything that is missing and how to fix it.

The checkup reads none of your documents and uses no network. When its last line reads Ready: the deterministic engine can run, you can start. On a machine without AI software it will list Ollama as missing, which is expected and does not matter for the deterministic engine.

3. Deterministic quick start

No further setup. Try it first on the synthetic example summons that ships with the package (an invented case, no real person), then on a folder of your own documents.

One document

R
f <- file.path(tempdir(), "synthetic_kc_printed_scanned.pdf")
download.file(paste0("https://raw.githubusercontent.com/evictionresearch/extract-text/",
                     "main/python/tests/fixtures/synthetic_kc_printed_scanned.pdf"),
              f, mode = "wb")

one <- extract_deterministic(f)
one$record$defendant_address      # the service address, split into parts
one$evidence$defendant_address    # the rule that found it, and where on the page
one$flags                         # empty means every check passed
record_to_row(one)                # the same result as a one-row tibble
Python
from extract_text import extract

result = extract("synthetic_kc_printed_scanned.pdf")      # rules only, the default
result.record.defendant_address.street
result.evidence                                           # where each field came from
result.flags
Terminal
extract-text extract synthetic_kc_printed_scanned.pdf

The example is a printed form that was scanned, so OCR reads it. The expected address is 1234-EXAMPLE AVE. NE BLDG ZZ Apt # 102, Sampleton, WA 98100, with no flags.

A folder of documents

R
results <- scan_documents("path/to/summonses/", engine = "deterministic",
                          out_dir = "path/to/results/", review = TRUE)
Python
from extract_text import scan

rows = scan("path/to/summonses/", engine="deterministic", out_dir="path/to/results/")
Terminal
extract-text scan path/to/summonses/ --engine deterministic --out path/to/results/ --review

Expect about 5 seconds a document when OCR is needed, and much less for e-filed PDFs that carry their own text. A document the rules cannot read gets a named flag instead of a guess.

4. AI quick start

Skip this section if AI is not permitted where you work. The AI engine needs one more program and a one-time model download.

Set up the local model, once

  1. Install Ollama (brew install ollama on macOS, or the installer at ollama.com) and start it.
  2. Download the model. It is about 7 GB, and nothing further is downloaded after this.
Terminal
ollama pull qwen3.5:9b

The model runs comfortably with about 16 GB of memory and reads roughly one page every 17 seconds on ordinary hardware. Run the checkup again; it reports whether Ollama is running and the model is present.

One document

R
model <- extract_ai("summons.pdf")      # local model, the default backend
model$record$defendant_address$raw
Python
result = extract("summons.pdf", engine="ai")
result.record.defendant_address.raw
Terminal
extract-text extract summons.pdf --engine ai

A folder of documents

R
results <- scan_documents("path/to/summonses/", engine = "ai",
                          out_dir = "path/to/results/", review = TRUE)
Python
rows = scan("path/to/summonses/", engine="ai", out_dir="path/to/results/")
Terminal
extract-text scan path/to/summonses/ --engine ai --out path/to/results/ --review

A language model can give a confident, fluent, wrong answer. Run alone, the AI engine's values are not checked against the document's text. When the rules engine runs too (the next section), each AI value is checked against the text the rules read.

5. Both engines quick start

Needs the AI setup from section 4. The rules fill the main columns; the AI's answers go in columns starting ai_; and the two are compared field by field.

One document

R
rules <- extract_deterministic("summons.pdf")
model <- extract_ai("summons.pdf")
compare_extractions(rules, model)$needs_review   # fields a person should look at
Python
both = extract("summons.pdf", engine="both")
both.record.defendant_address.street      # the rules' answer
both.ai.record.defendant_address.raw      # the AI's answer, kept separate
both.comparison.needs_review              # fields a person should look at
Terminal
extract-text extract summons.pdf --engine both

A folder of documents

R
results <- scan_documents("path/to/summonses/", engine = "both",
                          out_dir = "path/to/results/", review = TRUE)
Python
rows = scan("path/to/summonses/", engine="both", out_dir="path/to/results/")
Terminal
extract-text scan path/to/summonses/ --engine both --out path/to/results/ --review

Three columns appear only in this mode. address_similarity scores how alike the two addresses are, from 0 to 1. address_same_street is true when that score clears 0.7. case_number_agree says whether both engines read the same case number. Agreement between two independent methods is good evidence a value is right, and disagreement points to the documents worth a person's time.

6. What you get back

A folder run writes these files to the output folder you name.

  • extracted.csv, one row per document, which opens in anything.
  • extracted.jsonl, the full detail behind every cell, including each value's evidence and flags.
  • extracted.parquet, the same table in a faster format, when the parquet extra is installed (the R install includes it).
  • review/index.html, the checking page, when review is requested.
ColumnWhat it holds
defendant_namesDefendant names as printed, separated by semicolons
defendant_streetHouse number and street, including any unit printed on the street line
defendant_unitThe unit on its own. It repeats what is already in the street column, so use the street column alone for the full line
defendant_city, _state, _zipThe rest of the address
defendant_anchorThe rule that found the address (the audit trail)
plaintiffs, attorney_firm, case_numberOther parties and case details, as printed
text_sourcepdf_text_layer for digital text, or pdf_ocr and similar when OCR read the page
flagsNamed warnings, separated by semicolons. Empty means every check passed

The full column list is in the manual, section 10.

7. Check the results by hand

The review page shows each document's page image beside what the engine read, with flagged documents first. Opened as a plain file it is read-only. To save corrections, serve it with the package's own command, which opens it in your browser and writes each correction to corrections.jsonl in the results folder. Then score the engine against those corrections.

Terminal
extract-text review --out path/to/results/ --serve
extract-text score --out path/to/results/ --shapes

R users can run these in RStudio's Terminal tab. The command lives in the package's private Python environment, at the path this returns.

R
file.path(dirname(reticulate::virtualenv_python("r-extracttext")), "extract-text")

The score report masks every value (letters become A or a, digits become 9), so it can be shared without exposing anyone's name or address.

8. Privacy and your records

With the default engines, no document, page image, or extracted value leaves your computer. The deterministic engine has no network code in its path at all. The AI engine talks only to Ollama on your own machine. There is no telemetry and nothing checks for updates, so after installation everything runs offline.

The output files hold whatever the documents hold, names and addresses included. Keep them on governed storage, never in a code repository and never anywhere publicly served.

The rules were written for and measured on Washington State documents. Documents from another court, or newer forms, deserve a check by hand before their results are trusted. Section 16 of the manual covers adapting the rules.
