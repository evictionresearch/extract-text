Get started

From install to a table of cases

Eight steps in R, using the rules engine, which needs no AI setup. Each step is a few lines to copy and run. The local AI engine is experimental and is not used here.

Before step 1. You need R and RStudio on your computer, both free, and your court documents (PDF or TIFF files) in a folder on it. Your computer's system also has to be recent enough for the installs in step 1: on a Mac, macOS 15 (Sequoia) or later on an Apple chip (M1 or later), and on a PC, Windows 11. Step 1 says how to check.

Prefer one file to copy from? Every step on this page is in getting_started_example_script.R, under the same eight numbers and with more explanation. Save it, open it in RStudio, and run it a block at a time.

1 Install four free programs

extract-text needs four programs that R does not install.

  • poppler opens PDF files.
  • tesseract reads scanned pages (OCR).
  • Python 3.10 or newer runs the engine, which is written in Python. The Python that comes with a Mac is older.
  • git downloads the engine during the install.

You install them once, in a terminal window outside R. Find your computer below. You need the internet only to install. After that, extract-text runs with the network unplugged.

Check your system first, and update it if it is old.

  • Mac. Open the Apple menu and choose About This Mac. You need macOS 15 (Sequoia) or later, and a line that reads "Chip: Apple M1" or later. Homebrew, the installer used below, keeps ready-made copies of poppler, tesseract, and Python only for the three newest versions of macOS on Apple chips (in November 2026: macOS 15, 26, and 27). On macOS 14 or older, or on an Intel Mac, it prints a warning and tries to build each program from its source code, which is slow and can fail, as it did for one of our testers on macOS 14. Update macOS first, in System Settings, General, Software Update. For a Mac that cannot be updated, Homebrew's own advice is MacPorts, which we have not tested.
  • Windows. Press the Windows key, type winver, and press Enter. Windows 11 works with everything on this page. On Windows 10, the four programs and R need version 1809 or later, and the current RStudio lists Windows 11 only.

Mac

  1. Open Terminal. Press Command and Space, type Terminal, and press Return.
  2. Install Homebrew if you do not have it. Installing Homebrew also installs git.
  3. Run this line.
brew install poppler tesseract python

Windows

  1. Open PowerShell. Press the Windows key, type PowerShell, and press Enter.
  2. Run these four lines.
winget install oschwartz10612.Poppler
winget install UB-Mannheim.TesseractOCR
winget install Python.Python.3.12
winget install Git.Git
  1. Add tesseract to your PATH, which its installer does not do. Open Start, type "Edit environment variables for your account", and open it. Select Path, choose Edit, choose New, and enter C:\Program Files\Tesseract-OCR.
  2. Restart RStudio.

Linux (Debian or Ubuntu)

Run this line in a terminal.

sudo apt install poppler-utils tesseract-ocr python3 python3-venv git

On a work computer of any kind, installs may need your IT department. Ask for poppler, tesseract, Python 3.10 or newer, and git.

2 Install extract-text

In RStudio, install the package, then build the Python engine it runs on. You do this once per computer.

install.packages(c("remotes", "dplyr"))
remotes::install_github("evictionresearch/extract-text", subdir = "r")

library(extracttext)

# Two checks before the engine is built. The first should print the path of
# a Python, 3.10 or newer (NULL means R found none). The second should print
# the path of git (an empty "" means it is missing). If either fails, go
# back to step 1, restart RStudio, and run this block again.
reticulate::virtualenv_starter(">=3.10")
Sys.which("git")

extracttext_install()

The install prints many lines as it downloads the engine's parts. On a fast connection it takes under a minute. Restart R when it finishes, so the package finds the engine. In RStudio, choose Session, then Restart R. Then check your setup.

library(extracttext)
library(dplyr)

extracttext_doctor()

The last line of the checkup should be this one.

Ready: the deterministic engine can run.

The checkup reports Ollama as missing unless you set up the AI engine, and that is fine. The rules engine does not need it. If the checkup says the Python engine is not installed, see If something goes wrong.

3 Read one example document

This downloads a made-up summons from the package's test files and reads it.

f <- file.path(tempdir(), "synthetic_summons_scanned.pdf")
download.file(paste0("https://raw.githubusercontent.com/evictionresearch/",
                     "extract-text/main/python/tests/fixtures/",
                     "synthetic_summons_scanned.pdf"),
              f, mode = "wb")

# Open the summons, to compare with what the engine reads
browseURL(f)

one <- extract_deterministic(f)

# Expect 1234 EXAMPLE AVE S APT 5, Seattle, WA 98100
one$record$defendant_address

# Problems the engine found; empty means none
one$flags

4 Scan a random 50 of your own documents

Start with a random sample, not the whole folder. It takes minutes, and you grade every document in it in the next step.

Which documents to put in the folder. The engine reads one document at a time and writes one row for every file, whatever kind of document the file is. Its rules are built for the summons. If your folder holds whole case files (complaints, orders, returns of service), a case gets a row for each of them. When the file names say which documents are summonses, scan those alone, by giving scan_documents() a list of files in place of the folder.

summonses <- list.files(docs_dir, pattern = "summons", ignore.case = TRUE,
                        recursive = TRUE, full.names = TRUE)

If your documents are not from Washington. The rules that read the city and the state expect "WA" or "Washington" after the city. On a made-up Oregon summons and a made-up Texas one, the engine read the street, the unit, and the ZIP, left the city and state blank, and raised no flag. Every document you grade carries your city and state in the final table, and the others carry the street and ZIP alone. Documents from another state shows the four-line change that makes the engine read your state.

Practice first, on made-up documents. Steps 4 to 8 run on the package's 15 made-up documents as well as on real ones, so you can learn the grading page before you open a court record. This block downloads the package's code (about 10 MB) into a folder in your home directory. Run it, skip the docs_dir and results lines below, and go on from n_sample. The documents are few and partly repeat one another, so the practice scores mean nothing. Delete the folder when you are done.

practice <- path.expand("~/extract_text_practice")
dir.create(practice, showWarnings = FALSE)
download.file(paste0("https://github.com/evictionresearch/extract-text/",
                     "archive/refs/heads/main.zip"),
              file.path(practice, "extract-text.zip"), mode = "wb")
unzip(file.path(practice, "extract-text.zip"), exdir = practice)
docs_dir <- file.path(practice, "extract-text-main", "python", "tests",
                      "fixtures")
results  <- file.path(practice, "results")

docs_dir is the folder that holds your court documents (PDF or TIFF, subfolders included). results is a new folder where everything from here on is written. Type each path with forward slashes, on Windows too.

# Mac:     "/Users/yourname/Documents/court_documents"
# Windows: "C:/Users/yourname/Documents/court_documents"
docs_dir <- "path/to/your/documents"
results  <- "path/to/your/results"
n_sample <- 50

sample_dir <- file.path(results, "sample")
all_dir    <- file.path(results, "all")

res <- scan_documents(docs_dir, engine = "deterministic", sample = n_sample,
                      seed = 1, out_dir = sample_dir)

Expect about 5 seconds a document when OCR is needed. When the scan finishes, count what came back.

res %>%
  count(text_source,
        found   = defendant_street != "",
        flagged = flags != "")
# A tibble: 3 × 4
  text_source found flagged     n
  <chr>       <lgl> <lgl>   <int>
1 pdf_ocr     FALSE TRUE        1
2 pdf_ocr     TRUE  FALSE       4
3 pdf_ocr     TRUE  TRUE        1

This example comes from six made-up documents, so your counts will differ. found says whether the engine read a street, and flagged says whether it raised a flag. pdf_ocr means the pages were scans read by OCR.

Keep both folders private. Your documents and every file written from this step on hold tenants' names and addresses. Keep them wherever your organization keeps the court documents themselves, and out of any folder that syncs or is shared (Dropbox, iCloud Drive, OneDrive, or a Google Drive folder that syncs to your computer).

5 Grade the sample, then score the engine

Grading is required. Until you grade a sample, you do not know how often the scan is right on your documents.

This line opens a page in your browser that shows each document beside what the engine read. Check each field against the page, change only what is wrong, and leave a field blank when the document does not have it. Then look at the colored boxes on the page image, which show where the engine read each value. Drag a box that sits over the wrong place to the right one. Where a field has no box, press the field's button under the image and drag across the value. A box you draw is added to the ones already there, and a box in the wrong place is deleted with its cross. Save every document, even when the engine got everything right. The top of the page has the grading rules in brief, and its foot says what to do when you finish. Fifty documents take about an hour. You can stop at any point by pressing Esc in RStudio, and running the line again picks up where you left off.

review_documents(res, correct = TRUE, n = n_sample, draw = "random")

Then score the engine against your answers.

score_documents(res)
  field      checked right  near blank wrong
1 plaintiff        1     1     0     0     0
2 defendants       1     1     0     0     0
3 street           1     1     0     0     0
4 unit             1     1     0     0     0
5 city             1     0     0     0     1
6 state            1     1     0     0     0
7 zip              1     1     0     0     0

This example is the one made-up document graded in the video, where the engine misread the city. It is shortened to the main columns. With 50 graded documents, checked reads 50. The score has one row per field and counts how many documents the engine got right, nearly right (the right content written differently, such as Ave for Avenue), left blank, or got wrong. Two more columns, right_random and checked_random, give the accuracy estimate for the whole folder when you divide the first by the second.

Reading the score. Say the street row shows 43 right of 50 checked. The engine read the street right on 86 percent of your sample. Fifty documents is a small sample, so the share for the whole folder is probably between about 76 and 96 percent. Grade 100 or more before you publish counts or send anything to people.

Decide here whether the fields you need are accurate enough to scan everything. No score is right for everyone, so ask what the table is for. A count of filings by ZIP code can live with a street that is wrong one time in seven, and a mailing to tenants cannot. Look only at the fields you will use, and grade those with care, because a field you leave as the engine filled it is counted as right.

When a field you need is weak, there are three things to do.

  • The engine looked in the wrong place. Its box sat over the wrong part of the page, or the field had no box. Step 6 can fix that for your court's forms, with no code.
  • The box was in the right place and the value was still wrong. A rule has to change. Improve it shows how to tell us what goes wrong and how to change a rule on your own copy.
  • Grade more. Whatever the score, every document you grade is right in the final table. For a small folder, grading all of it is a sound plan.

Your corrections do not change the engine's rules. They tell you which fields to trust, every document you grade carries your answer in the final table, and your boxes teach the engine your court's forms in the next step. How the rules improve says how the rules themselves get better.

6 Teach the engine your court's forms

This step is optional and needs no code. Courts print their own forms, and a form can put the tenant's address where the engine's rules do not look. The boxes you fixed and drew while grading show where your court's forms print each field. From them the package writes a template for each form that has at least five graded documents.

learn_templates(res)

# Opens a page showing each template over a page it was learned from
review_templates(res)

# Approve each template whose regions sit where the form prints that field
approve_template("form-1", res)

Nothing learned is used until you approve it. A template holds the form's printed words and a region of the page for each field. It holds no names or addresses.

Expect templates only for the forms your court uses most. A random 50 rarely holds five documents of a rare form, and the engine reads those with its rules alone. A template changes where the engine looks, not how it reads. Form templates says more.

7 Scan the whole folder and grade a second 50

The full run goes to its own folder, so the sample and its corrections stay as they are. It uses the templates you approved in step 6, and the rules alone if you approved none. It needs no attention while it runs. At about 5 seconds a document, 4,000 documents take five or six hours.

templates_dir <- file.path(sample_dir, "templates")
use_templates <- dir.exists(templates_dir) &&
  any(list_templates(templates_dir)$approved)

res_all <- scan_documents(docs_dir, engine = "deterministic", out_dir = all_dir,
                          templates = if (use_templates) templates_dir)

The first sample told you whether to run everything. A second sample measures the run that becomes your table, templates included.

review_documents(res_all, correct = TRUE, n = n_sample, draw = "random", seed = 1)

score_documents(res_all)

The share right in this score is the accuracy of the full run. Report it with the table.

8 Build the final table

cases <- case_table(res_all, graded = sample_dir,
                    save = file.path(results, "case_table.csv"))

# How many rows carry a graded answer, and how many the engine's reading
count(cases, source)
# A tibble: 2 × 2
  source     n
  <chr>  <int>
1 engine     5
2 graded     1

The table has one row per document, with the case number, the plaintiff, the defendants, and the defendants' address. Your graded answers from both samples replace the engine's wherever you gave one, and the source column says which each row carries. In this example, from the six made-up documents, one row carries a graded answer and five carry the engine's reading. The table is saved as case_table.csv in your results folder.

If something goes wrong

Run the checkup first. extracttext_doctor() in R looks at your computer and prints the command for anything missing.

The checkup says "The Python engine is not installed yet." Restart R and run it again. If the message stays, the install in step 2 stopped early, most often because Python was missing or older than 3.10. Run the two checks in step 2, fix what they show, and install again.

If the install finished and the message still stays, something has told R to use another Python. In a fresh R session, point R at the engine's own environment before anything else, then run the checkup.

library(extracttext)
reticulate::use_virtualenv("r-extracttext", required = TRUE)
extracttext_doctor()

Something else. Open an issue at github.com/evictionresearch/extract-text/issues, or write to evictions@berkeley.edu.

Never paste a real document, name, address, or case number into an issue or an email. Describe the problem, or reproduce it with the made-up example document from step 3.

Python and the command line

The eight steps above use R. The same engine runs from Python and from a terminal. Install the four programs from step 1 first. Then make a private Python environment for the engine and turn it on. Python from Homebrew on a Mac, and from Debian or Ubuntu, refuses a plain pip install outside one.

python3 -m venv ~/extract-text-env
source ~/extract-text-env/bin/activate
pip install "extract-text @ git+https://github.com/evictionresearch/extract-text#subdirectory=python"
extract-text doctor

On Windows, skip the first two lines. On a Mac or Linux, run the source line again in every new terminal window. Start here gives the terminal command for each of the eight steps.

from extract_text import extract, scan

result = extract("summons.pdf")                 # rules only, no AI
result.record.defendant_address.street
result.flags                                    # empty means all checks passed

rows = scan("documents/", engine="deterministic", out_dir="results/")

From a terminal, with no programming, this line scans a folder.

extract-text scan documents/ --engine deterministic --out results/ --review

A folder scan writes extracted.csv, the table. It also writes extracted.jsonl, the full record of where each value came from, and review/index.html, a page that shows each flagged document beside what was read from it.
