Open-source software from the Eviction Research Network

extract-text reads eviction court documents into a table.

Many courts keep eviction filings only as page images, and a filing cannot be counted or mapped until it is in a table. extract-text reads e-filed PDFs, scanned PDFs, and TIFF images and returns one row per document, with the plaintiffs, the defendants, the address where the defendants were served, the plaintiff’s attorney, and the case number.

Free and open source. It runs on your own computer, from R or Python, on Mac, Windows, and Linux.

Under development · version 0.4.0

Get started How it works

Two engines

Rules, a local AI model, or both

You choose the engine on each run.

No AI of any kind

The rules engine

It reads with written rules and the layout of the page. A scanned page is first turned into text by OCR (optical character recognition). The same document always gives the same output, so the code and the manual call it the deterministic engine. Every value records the rule that found it and where on the page it was found. It uses no AI and no network connection, so agencies whose policies do not permit AI tools can use it alone.

Optional

The local AI engine

A language model reads the page images. It runs on your own computer through Ollama, a free program that runs AI models locally, and it sends nothing to any cloud service. It reads what rules and OCR cannot, handwriting above all.

When you run both, the package compares the two addresses on every document and flags each disagreement for a person to review. Either engine also flags a value it is unsure of. Neither guesses a value to keep a row looking complete.

Privacy

Your documents stay on your computer

Court filings carry tenants' names and addresses. With the default engines, the documents, the page images, and the extracted values never leave your computer. The package sends no usage data, and once installed it runs with the network unplugged. Every example and test document in the code repository is made up.

Accuracy

Grade a random 50 before you trust a run

The Eviction Research Network wrote and measured the rules on Washington State filings. Another court's forms, scan quality, or decade can make them misread a field without raising a flag, and accuracy differs by field. On a random 50 King County summonses from 2017, the rules engine read the street right on about 85 percent and the plaintiff on about 40 percent (October 2026).

So the first run is a random 50 of your own documents. You grade them on a review page that shows each document beside what the engine read. The package scores the engine against your answers. You scan the whole folder only when the fields you need are accurate enough.

First steps

Getting started, in outline

The Get started page has seven steps, each a few lines of R to copy and run. They fall into three stages.

1

Steps 1 and 2

Install

Install four free programs that open PDFs, read scanned pages, and run the engine (poppler, tesseract, Python, and git), then extract-text itself. A checkup looks at your computer and names anything missing.

2

Steps 3 to 5

Test on a sample

Read a made-up summons, scan a random 50 of your own documents, grade them on the review page, and score the engine.

3

Steps 6 and 7

Run the whole folder

Scan every document, grade a second random 50, and build the final table of cases.

Uses

Who extract-text is for

The Eviction Research Network built extract-text for work that describes or reduces displacement. That work includes research, legal services, journalism, policy analysis, court administration, and tenant defense.

Running extract-text takes someone who works in R, Python, or a terminal. If that is not you, send this page to an analyst on your staff or at a partner organization, or write to evictions@berkeley.edu.

An eviction filing is not a finding of wrongdoing. The project does not support tenant screening, landlord blacklists, debt collection, or the use of these records to locate people for enforcement.
