Get started

From install to a table of cases

Seven steps in R, using the rules engine, which needs no AI setup. Each step is a few lines to copy and run.

Before step 1. You need R and RStudio on your computer, both free, and your court documents (PDF or TIFF files) in a folder on it.

1 Install four free programs

extract-text needs four programs that R does not install.

  • poppler opens PDF files.
  • tesseract reads scanned pages (OCR).
  • Python 3.10 or newer runs the engine, which is written in Python. The Python that comes with a Mac is older.
  • git downloads the engine during the install.

You install them once, in a terminal window outside R. Find your computer below. You need the internet only to install. After that, extract-text runs with the network unplugged.

Mac

  1. Open Terminal. Press Command and Space, type Terminal, and press Return.
  2. Install Homebrew if you do not have it. Installing Homebrew also installs git.
  3. Run this line.
brew install poppler tesseract python

Windows

  1. Open PowerShell. Press the Windows key, type PowerShell, and press Enter.
  2. Run these four lines.
winget install oschwartz10612.Poppler
winget install UB-Mannheim.TesseractOCR
winget install Python.Python.3.12
winget install Git.Git
  1. Add tesseract to your PATH, which its installer does not do. Open Start, type "Edit environment variables for your account", and open it. Select Path, choose Edit, choose New, and enter C:\Program Files\Tesseract-OCR.
  2. Restart RStudio.

Linux (Debian or Ubuntu)

Run this line in a terminal.

sudo apt install poppler-utils tesseract-ocr python3 python3-venv git

On a work computer of any kind, installs may need your IT department. Ask for poppler, tesseract, Python 3.10 or newer, and git.

2 Install extract-text

In RStudio, install the package, then build the Python engine it runs on. You do this once per computer.

install.packages(c("remotes", "dplyr"))
remotes::install_github("evictionresearch/extract-text", subdir = "r")

library(extracttext)
extracttext_install()

Restart R so the package finds the engine. In RStudio, choose Session, then Restart R. Then check your setup.

library(extracttext)
library(dplyr)

extracttext_doctor()

The last line of the checkup should be this one.

Ready: the deterministic engine can run.

The checkup reports Ollama as missing unless you set up the AI engine, and that is fine. The rules engine does not need it. If the checkup says the Python engine is not installed, see If something goes wrong.

3 Read one example document

This downloads a made-up summons from the package's test files and reads it.

f <- file.path(tempdir(), "synthetic_summons_scanned.pdf")
download.file(paste0("https://raw.githubusercontent.com/evictionresearch/",
                     "extract-text/main/python/tests/fixtures/",
                     "synthetic_summons_scanned.pdf"),
              f, mode = "wb")

# Open the summons, to compare with what the engine reads
browseURL(f)

one <- extract_deterministic(f)

# Expect 1234 EXAMPLE AVE S APT 5, Seattle, WA 98100
one$record$defendant_address

# Problems the engine found; empty means none
one$flags

4 Scan a random 50 of your own documents

Start with a random sample, not the whole folder. It takes minutes, and you grade every document in it in the next step.

docs_dir is the folder that holds your court documents (PDF or TIFF, subfolders included). results is a new folder where everything from here on is written. Type each path with forward slashes, on Windows too.

# Mac:     "/Users/yourname/Documents/court_documents"
# Windows: "C:/Users/yourname/Documents/court_documents"
docs_dir <- "path/to/your/documents"
results  <- "path/to/your/results"
n_sample <- 50

sample_dir <- file.path(results, "sample")
all_dir    <- file.path(results, "all")

res <- scan_documents(docs_dir, engine = "deterministic", sample = n_sample,
                      seed = 1, out_dir = sample_dir)

Expect about 5 seconds a document when OCR is needed. When the scan finishes, count what came back.

res %>%
  count(text_source,
        found   = defendant_street != "",
        flagged = flags != "")
# A tibble: 3 × 4
  text_source found flagged     n
  <chr>       <lgl> <lgl>   <int>
1 pdf_ocr     FALSE TRUE        1
2 pdf_ocr     TRUE  FALSE       4
3 pdf_ocr     TRUE  TRUE        1

This example comes from six made-up documents, so your counts will differ. found says whether the engine read a street, and flagged says whether it raised a flag. pdf_ocr means the pages were scans read by OCR.

Keep both folders private. Your documents and every file written from this step on hold tenants' names and addresses. Keep them wherever your organization keeps the court documents themselves, and out of any folder that syncs or is shared (Dropbox, iCloud Drive, OneDrive, or a Google Drive folder that syncs to your computer).

5 Grade the sample, then score the engine

Grading is required. Until you grade a sample, you do not know how often the scan is right on your documents.

This line opens a page in your browser that shows each document beside what the engine read. Change only what is wrong, leave a field blank when the document does not have it, and save. Fifty documents take about an hour. You can stop at any point by pressing Esc in RStudio, and running the line again picks up where you left off.

review_documents(res, correct = TRUE, n = n_sample, draw = "random")

Then score the engine against your answers.

score_documents(res)
  field      checked right  near blank wrong
1 plaintiff        1     1     0     0     0
2 defendants       1     1     0     0     0
3 street           1     1     0     0     0
4 unit             1     1     0     0     0
5 city             1     0     0     0     1
6 state            1     1     0     0     0
7 zip              1     1     0     0     0

This example is the one made-up document graded in the video, where the engine misread the city. It is shortened to the main columns. With 50 graded documents, checked reads 50. The score has one row per field and counts how many documents the engine got right, nearly right, left blank, or got wrong. Two more columns, right_random and checked_random, give the accuracy estimate for the whole folder when you divide the first by the second.

Decide here whether the fields you need are accurate enough to scan everything. Fifty random documents put the share right within about 10 points. Grade 100 or more before you publish counts or send anything to people.

Your corrections do not change the engine. They tell you which fields to trust, and every document you grade carries your answer in the final table.

6 Scan the whole folder and grade a second 50

The full run goes to its own folder, so the sample and its corrections stay as they are. It needs no attention while it runs. At about 5 seconds a document, 4,000 documents take five or six hours.

res_all <- scan_documents(docs_dir, engine = "deterministic", out_dir = all_dir)

The first sample told you whether to run everything. A second sample measures the run that becomes your table.

review_documents(res_all, correct = TRUE, n = n_sample, draw = "random", seed = 1)

score_documents(res_all)

The share right in this score is the accuracy of the full run. Report it with the table.

7 Build the final table

cases <- case_table(res_all, graded = sample_dir,
                    save = file.path(results, "case_table.csv"))

# How many rows carry a graded answer, and how many the engine's reading
count(cases, source)
# A tibble: 2 × 2
  source     n
  <chr>  <int>
1 engine     5
2 graded     1

The table has one row per document, with the case number, the plaintiff, the defendants, and the defendants' address. Your graded answers from both samples replace the engine's wherever you gave one, and the source column says which each row carries. In this example, from the six made-up documents, one row carries a graded answer and five carry the engine's reading. The table is saved as case_table.csv in your results folder.

Go further

  • The full script. getting_started_example_script.R holds every step on this page with more explanation, plus two optional ones.
  • Teach the engine your forms, without code. While you grade, you can draw a box where your court's form prints each field. The package learns a template from those boxes, and nothing learned is used until you approve it. The guide is the last chapter of Changing the rules.
  • Set up the AI engine. It is optional and needs about 16 GB of memory. Section 6 of the manual has the two steps.
  • Read the manual. The manual covers every output column, the flags, and how to use the package outside Washington.

If something goes wrong

Run the checkup first. extracttext_doctor() in R looks at your computer and prints the command for anything missing.

The checkup says "The Python engine is not installed yet." Restart R and run it again. If the message stays, R may be using another Python project on your computer, such as a .venv folder in your working directory. Point R at the engine's own environment, then run the checkup again.

library(extracttext)
reticulate::use_virtualenv("r-extracttext", required = TRUE)
extracttext_doctor()

Something else. Open an issue at github.com/evictionresearch/extract-text/issues, or write to evictions@berkeley.edu.

Never paste a real document, name, address, or case number into an issue or an email. Describe the problem, or reproduce it with the made-up example document from step 3.

Python and the command line

The seven steps above use R. The same engine runs from Python and from a terminal. Install the four programs from step 1 first.

pip install "extract-text @ git+https://github.com/evictionresearch/extract-text#subdirectory=python"
extract-text doctor
from extract_text import extract, scan

result = extract("summons.pdf")                 # rules only, no AI
result.record.defendant_address.street
result.flags                                    # empty means all checks passed

rows = scan("documents/", engine="deterministic", out_dir="results/")

From a terminal, with no programming, this line scans a folder.

extract-text scan documents/ --engine deterministic --out results/ --review

A folder scan writes extracted.csv, the table. It also writes extracted.jsonl, the full record of where each value came from, and review/index.html, a page that shows each flagged document beside what was read from it.
